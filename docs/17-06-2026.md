# Issue with Agent 2: Regex Parser Failing on Qwen 2.5

## What is happening?
We are facing an issue with **Agent 2** where the system isn't taking actions properly, even though the underlying AI model is doing its job correctly.

1. **The AI does its part:** When we use **Qwen 2.5**, the assistant understands the prompt perfectly and writes out a correct, completely valid response. 
2. **The parser fails:** The code uses a text-matching tool (**Regex**) to look for very specific words or symbols to figure out what the AI wants to do next. However, because Qwen 2.5 words things slightly differently or adds extra spaces/markdown tags, the Regex code fails to read it.

Basically, the AI is giving the right answer, but our code is too rigid to understand it.

---

## How to fix it (Options)

### Fix 1: Make the AI output JSON (Highly Recommended)
Instead of letting the AI write normal text and trying to guess the meaning with Regex, we should force **Qwen 2.5** to reply strictly in a **JSON** format.
* **Why it helps:** JSON is a structured format that code can easily read without needing complex text-matching logic. 
* **How to do it:** Update the system prompt or use the model's native JSON mode to say: *"Return your answer only as a JSON object matching this exact format."*

### Fix 2: Find a temporary parsing alternative
If we cannot change the AI's output format right now because it might break other parts of the system, we need to replace the rigid Regex code with something more flexible.
* **Why it helps:** A simple fallback string search (like splitting text by lines or scanning for specific keywords regardless of spaces) can keep the agent running for now.
* **How to do it:** Write a basic helper function that handles messy text better than Regex does.
